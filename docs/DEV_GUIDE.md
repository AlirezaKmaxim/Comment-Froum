## ۱. تغییر استایل‌های بخش فرانت‌اند (Front-end)

بخش کاربری افزونه (فرم ارسال نظرات، لیست دیدگاه‌ها، ستاره‌های امتیازدهی و دکمه‌ها) با استفاده از **Tailwind CSS v4** طراحی شده است. 

### فایل‌های مرتبط با فرانت‌اند:
*   **فایل قالب (HTML/PHP):** `src/Front/View.php` - شامل ساختار HTML و کلاس‌های Tailwind فرانت‌اَند.
*   **منبع اصلی استایل‌ها (CSS Source):** `src/input.css` - استایل‌های سفارشی، متغیرهای تم و کدهای CSS خالص در اینجا نوشته می‌شوند.
*   **خروجی نهایی کامپایل‌شده:** `assets/front/front.css` - فایل نهایی و مینیفای‌شده که توسط وردپرس لود می‌شود. **هرگز این فایل را به صورت دستی ویرایش نکنید** چون با هر بار کامپایل، تغییرات آن از بین می‌رود.

### مراحل تغییر استایل‌های فرانت‌اند به صورت قدم‌به‌قدم:

#### گام اول: نصب وابستگی‌های توسعه (نود جی‌اس)
مطمئن شوید برنامه Node.js روی سیستم شما نصب است. ترمینال را در مسیر اصلی افزونه باز کرده و دستور زیر را اجرا کنید تا پکیج‌های Tailwind CSS v4 نصب شوند:
```bash
npm install
```

#### گام دوم: اجرای دستور کامپایل خودکار (Watch Mode)
در حین طراحی و کدنویسی، دستور زیر را در ترمینال اجرا کنید:
```bash
npm run dev
```
این دستور، فایل‌های پروژه را مانیتور (Watch) می‌کند. با هر تغییری که در فایل‌های PHP بخش فرانت یا فایل `src/input.css` ایجاد کرده و ذخیره کنید، استایل‌ها در کسری از ثانیه کامپایل شده و در `assets/front/front.css` قرار می‌گیرند.

#### گام سوم: اعمال تغییر در HTML یا کدهای CSS
*   **روش الف) افزودن کلاس‌های ابزاری Tailwind در قالب:**
    فایل `src/Front/View.php` را باز کنید. کلاس‌های مورد نظر خود را به المان‌ها اضافه کنید. برای مثال، برای تغییر رنگ دکمه ثبت نظر، کلاس‌های مربوطه را در دکمه پیدا کرده و تغییر دهید:
    ```html
    <!-- نمونه تغییر رنگ دکمه از سبز پیش‌فرض به رنگ دلخواه -->
    <button class="bg-primary hover:bg-teal text-white px-6 py-3 rounded-xl transition-all">
        ثبت دیدگاه
    </button>
    ```
*   **روش ب) نوشتن CSS سفارشی و متغیرهای تم:**
    فایل `src/input.css` را باز کنید. متغیرهای اصلی تم در بخش `@theme` تعریف شده‌اند:
    ```css
    @theme {
      --color-primary: #0c2d28; /* رنگ تیره اصلی */
      --color-gold: #c39854;    /* رنگ طلایی دکمه‌ها و ستاره‌ها */
      --color-teal: #009c8f;    /* رنگ سبز/آبی فرعی */
      --font-peyda: Peyda, IRANSansX, Tahoma, sans-serif;
    }
    ```
    شما می‌توانید کدهای CSS خالص خود را در انتهای این فایل و داخل بلاک اسکوپ `.md-custom-comments-scope` بنویسید تا فقط روی این افزونه اعمال شوند.

#### گام چهارم: خروجی نهایی برای انتشار (Production Build)
پس از اتمام طراحی و قبل از آپلود افزونه روی سرور اصلی، دستور زیر را اجرا کنید تا فایل استایل‌ها فشرده و بهینه‌سازی شود:
```bash
npm run build
```

## ۲. تغییر استایل‌های پنل مدیریت (Admin Panel)

سیستم استایل‌دهی پنل مدیریت هم مثل فرانت‌اند با **Tailwind CSS v4 از پیش کامپایل‌شده** ساخته می‌شود (قبلاً از نسخه Runtime/جاوااسکریپتی Tailwind استفاده می‌شد که حجم آن حدود ۴۰۰ کیلوبایت بود و کلاس‌ها را در لحظه‌ی بارگذاری هر صفحه در مرورگر کامپایل می‌کرد؛ برای کاهش حجم دانلود و هزینه پردازش کلاینت به یک فایل CSS از پیش کامپایل‌شده تغییر کرد). کتابخانه تعاملی **Alpine.js** هم مثل قبل برای منطق تب‌ها/مودال‌ها استفاده می‌شود.

> [!IMPORTANT]
> برخلاف قبل، بعد از تغییر کلاس‌های Tailwind در `src/Admin/Views/settings-page.php` باید دستور `npm run build:admin` (یا `npm run build` که هر دو خروجی فرانت و ادمین را می‌سازد) را اجرا کنید تا `assets/admin/admin-tailwind.css` به‌روزرسانی شود؛ در غیر این‌صورت کلاس جدید در پنل ادمین اعمال نمی‌شود.

### فایل‌های مرتبط با پنل مدیریت:
*   **منطق کنترلر (PHP):** `src/Admin/Controllers/SettingsController.php` - فقط منطق AJAX handlerها و آماده‌سازی متغیرهای مورد نیاز صفحه تنظیمات.
*   **قالب HTML/Alpine.js صفحه تنظیمات:** `src/Admin/Views/settings-page.php` - تمام بخش‌های دیداری پنل مدیریت، تب‌ها، فیلدها و پنجره‌های پاپ‌آپ با Tailwind و Alpine.js در همین فایل طراحی شده‌اند (با `include` از داخل `SettingsController::render_settings_page()` فراخوانی می‌شود).
*   **منبع استایل ادمین (CSS Source):** `src/admin-input.css` - توکن‌های رنگ تم ادمین (`@theme`) اینجا تعریف می‌شوند.
*   **خروجی نهایی کامپایل‌شده ادمین:** `assets/admin/admin-tailwind.css` - **هرگز دستی ویرایش نشود**؛ با `npm run build:admin` بازتولید می‌شود.
*   **لودر اسکریپت‌ها/استایل‌ها (PHP):** `src/Admin/Assets.php` - enqueue کردن `admin-tailwind.css` و Alpine.js.

### مراحل تغییر استایل‌های پنل مدیریت به صورت قدم‌به‌قدم:

#### گام اول: ویرایش مستقیم کلاس‌های قالب ادمین
فایل `src/Admin/Views/settings-page.php` را باز کنید. شما می‌توانید کلاس‌های Tailwind را مستقیماً ویرایش کنید:
```html
<!-- تغییر رنگ پس‌زمینه هدر تنظیمات در فایل settings-page.php -->
<div class="bg-primary p-8 text-white flex items-center justify-between border-b-4 border-gold">
```
اگر می‌خواهید رنگ هدر را به خاکستری تیره تغییر دهید، کافیست `bg-primary` را به `bg-gray-800` تغییر دهید، دستور `npm run build:admin` را اجرا کنید و صفحه پیشخوان را رفرش کنید.

#### گام دوم: سفارشی‌سازی پلت رنگ‌ها (تم ادمین)
رنگ‌های اختصاصی پنل مدیریت (مانند `primary` و `gold`) در فایل `src/admin-input.css` به‌صورت توکن‌های `@theme` تعریف شده‌اند (دقیقاً همان الگوی `src/input.css` برای فرانت‌اند). اگر می‌خواهید رنگ‌های اصلی تم پنل مدیریت را تغییر دهید، این فایل را باز کرده و مقادیر را ویرایش کنید، سپس `npm run build:admin` را اجرا کنید:
```css
/* فایل src/admin-input.css */
@theme {
  --color-primary: #0c2d28; /* رنگ هدر و دکمه‌های اصلی */
  --color-gold: #c39854;    /* رنگ برچسب‌ها و حاشیه‌ها */
  --color-teal: #009c8f;    /* رنگ وضعیت‌ها و دکمه‌های فرعی */
}
```

#### گام سوم: کار با تعاملات Alpine.js در پنل مدیریت
بسیاری از بخش‌های تعاملی ادمین (مانند سوئیچ کردن بین تب‌ها، پاپ‌آپ‌های پاسخ‌دهی و ویرایش دیدگاه‌ها) بدون نیاز به جی‌کوئری و با Alpine.js هندل می‌شوند.
*   **تغییر استایل تب فعال:** دکمه‌های منوی سمت راست با متغیر `activeTab` کنترل می‌شوند:
    ```html
    :class="activeTab === 'general' ? 'bg-primary text-white shadow-md' : 'text-gray-700 hover:bg-gray-200'"
    ```
*   **استایل‌دهی پاپ‌آپ‌ها (Modals):** پاپ‌آپ پاسخ‌دهی با بررسی متغیر `replyingTo !== null` نمایش داده می‌شود. برای ویرایش افکت یا ظاهر آن، کدهای مربوط به مودال را در انتهای فایل پیدا کرده و کلاس‌های ظاهر آن را تغییر دهید.

## ۳. نکات طلایی برای جلوگیری از تداخل استایل‌ها

به دلیل ماهیت وردپرس، ممکن است کدهای CSS قالب یا پلاگین‌های دیگر (به ویژه صفحه‌سازهایی مثل المنتور یا دیوی) روی ظاهر افزونه تأثیر بگذارند. برای پیشگیری از این تداخل‌ها قوانین زیر را رعایت کنید:

1.  **استفاده از کلاس اسکوپ (Scope Class):**
    تمام محتوای خروجی فرانت‌اند افزونه در قالب یک تگ با کلاس لایه محافظتی `.md-custom-comments-scope` قرار دارد. در فایل `src/input.css` هر کلاسی که تعریف می‌کنید را حتماً در زیرمجموعه این کلاس بنویسید:
    ```css
    .md-custom-comments-scope {
        /* کدهای شما در این قسمت */
        .my-custom-btn {
            border-radius: 50px;
        }
    }
    ```
2.  **استفاده از دستور مهم بودن (`!important`):**
    اگر قالبی اصرار به تغییر استایل فیلدها یا دکمه‌های افزونه شما داشت، در فایل `src/input.css` بعد از مقدار استایل، علامت `!important` را قرار دهید تا مرورگر اولویت را به افزونه شما بدهد:
    ```css
    .md-custom-comments-scope .comment-submit-btn {
        background-color: var(--color-gold) !important;
        font-size: 16px !important;
    }
    ```

## ۴. عیب‌یابی و عدم نمایش تغییرات (حل مشکل کش)

اگر استایل‌ها را تغییر دادید اما در مرورگر ظاهر جدید را مشاهده نکردید:

1.  **کش مرورگر (Browser Cache):**
    مرورگرها فایل‌های CSS را کش می‌کنند. با کلیدهای ترکیبی `Ctrl + F5` (یا `Cmd + Shift + R` در مک) صفحه را مجدداً بدون استفاده از کش بارگذاری کنید.
2.  **کش وردپرس و افزونه‌های بهینه‌سازی:**
    افزونه‌های کش مانند **WP Rocket** یا **LiteSpeed Cache** صفحات و فایل‌های CSS ترکیبی را ذخیره می‌کنند. این افزونه به صورت خودکار با ذخیره تنظیمات در ادمین، کش را پاک می‌کند، اما در حین توسعه در فرانت‌اَند بهتر است افزونه کش خود را موقتاً غیرفعال کنید یا دکمه **Clear Cache / Purge All** را در نوار بالای مدیریت وردپرس بزنید.
3.  **بررسی خطاهای کامپایل:**
    اگر در حین کار با `npm run dev` خطایی در ساختار CSS داشته باشید، در ترمینال پیغام خطای قرمز رنگ نمایش داده می‌شود و فایل `front.css` ساخته نخواهد شد. ترمینال را همیشه بررسی کنید تا مطمئن شوید بیلد با موفقیت انجام شده است.
